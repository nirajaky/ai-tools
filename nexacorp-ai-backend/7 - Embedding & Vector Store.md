# Embedding and Vector Store in Spring AI + RAG

In a Spring AI and RAG application, embeddings convert your documents into numerical representations, and a vector store saves those representations so your application can retrieve relevant information when a user asks a question.

Let's understand this using your example of ingesting PDFs, Wiki pages, and database content into a RAG application.

## 1. First, understand the complete RAG architecture

Source documents

PDFs · Wiki · Database

Ingestion + Chunking

Extract text and split into smaller chunks

Embedding Model

Convert each text chunk into a numerical vector

Vector Store

Store vectors, text chunks, and metadata

At question time, the same embedding model converts the user's query into a vector. The vector store retrieves relevant chunks for the LLM.

There are two main phases:

- Ingestion phase: Your documents are processed, embedded, and stored.
- Retrieval phase: A user asks a question, relevant chunks are retrieved, and Spring AI sends them to the LLM as context.

## 2. What is an embedding?

An embedding is a list of numbers generated by an embedding model to represent the meaning of a piece of text.

For example, suppose your PDF contains these sentences:

- "Spring Boot is used to build Java microservices."
- "Spring Boot helps developers create backend services."
- "The weather is sunny today."

An embedding model converts each sentence into a numerical vector.

Conceptually, the results might look like this:

Sentence 1

Spring Boot is used to build Java microservices.

[0.21, -0.45, 0.78, 0.12, ...]

Sentence 2

Spring Boot helps developers create backend services.

[0.19, -0.41, 0.75, 0.15, ...]

Sentence 3

The weather is sunny today.

[-0.62, 0.33, 0.08, -0.71, ...]

Illustrative values only. Real embeddings may contain hundreds or thousands of dimensions.

Notice that the first two sentences have similar meanings, so their vectors may be close together in the embedding space. The weather sentence will generally be farther away.

The embedding model does not simply assign one number to each word. It generates a multidimensional representation of the text's semantic information.

### Why are embeddings important in RAG?

Imagine a user asks:

> How can I develop backend services using Java?

Your document might contain the sentence:

> Spring Boot is used to build Java microservices.

The exact words are different, but their meanings are related. Embedding-based retrieval can find the relevant sentence even without an exact keyword match.

Important: Similarity is not the same as factual correctness. Good chunking, suitable embedding models, metadata filtering, and retrieval configuration still matter.

## 3. What is a vector store?

A vector store is a system that stores embedding vectors and lets your application search for vectors that are similar to a query vector.

Think of it as a specialized search database for your RAG application.

A vector store commonly stores three things together:

| Field            | Example                                          |
| ---------------- | ------------------------------------------------ |
| Text chunk       | Spring Boot is used to build Java microservices. |
| Embedding vector | `[0.21, -0.45, 0.78, ...]`                       |
| Metadata         | `source=java-guide.pdf`, `page=12`               |

When a user asks a question, the vector store searches for relevant chunks using similarity measures such as cosine similarity or other supported search methods.

## 4. How Spring AI handles embeddings and vector stores

Spring AI provides abstractions so your application can work with different embedding models and vector databases without writing all the low-level integration code yourself.

The important interfaces are:

`EmbeddingModel`

Converts text into embedding vectors using a configured embedding provider/model.

`VectorStore`

Provides common operations for adding documents, searching for similar documents, and deleting documents, subject to the implementation's capabilities.

`Document`

Represents a text document or chunk, typically including its content and metadata.

For example, your application might use:

- `EmbeddingModel` backed by an embedding API or a local embedding model.
- `VectorStore` backed by PostgreSQL/pgvector or Redis.
- `ChatClient` to communicate with the LLM that generates the final answer.

Spring AI handles much of the integration between these components through its configured implementations.

## 5. What happens during document ingestion?

Suppose your company has 100 PDF files, 50 Wiki pages, and data from a database.

Your Spring AI ingestion pipeline might look like this:

1. Load the source data. Use document readers or custom loaders to extract content from PDFs, Wiki pages, and databases.
2. Chunk the content. Split large documents into smaller, meaningful pieces. For example, one PDF might produce 200 chunks.
3. Generate embeddings. Send each chunk to the embedding model to obtain a numerical vector.
4. Store the data. Save the chunk, its vector, and useful metadata in your vector store.

For example, one document could become:

```
Document: java-guide.pdf

Chunk 1:
"Spring Boot simplifies the development of Java microservices."

Chunk 2:
"Spring Security supports authentication and authorization."

Chunk 3:
"Resilience4j provides circuit breaker and retry patterns."
```

Each chunk receives its own embedding and is stored as a searchable document.

The vector store is not normally just a collection of numerical vectors. The associated text and metadata are essential because the LLM needs readable information to answer the question.

## 6. What happens when a user asks a question?

Suppose the user asks your application:

> How do I implement a circuit breaker in Spring Boot?

Here is the retrieval flow.

1\. User query

"How do I implement a circuit breaker?"

2\. Embedding model

Converts the query into a vector

3\. Vector store search

Finds the most relevant document chunks

4\. Retrieved context

Spring Boot + Resilience4j documentation

5\. Chat model / LLM

Uses the query and retrieved context to generate an answer

6\. Answer returned to user

The critical detail is that the embedding model is used twice:

- During ingestion, it embeds each document chunk.
- During retrieval, it embeds the user's question.

Ideally, both operations use compatible embedding models and the same embedding space. If you change embedding models, you generally need to re-embed the existing documents.

## 7. Practical Spring AI code example

Let's look at a simplified implementation using Spring AI's `VectorStore` abstraction.

### A. Add documents to the vector store

```
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

import java.util.List;
import java.util.Map;

@Service
public class KnowledgeIngestionService {

    private final VectorStore vectorStore;

    public KnowledgeIngestionService(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public void ingestDocuments() {

        List<Document> documents = List.of(
            new Document(
                "Spring Boot simplifies Java microservice development.",
                Map.of("source", "java-guide.pdf")
            ),
            new Document(
                "Resilience4j provides circuit breaker functionality.",
                Map.of("source", "resilience-guide.pdf")
            )
        );

        vectorStore.add(documents);
    }
}
```

What happens when `vectorStore.add(documents)` executes?

1. Spring AI passes the documents through the configured vector-store implementation.
2. The implementation uses the configured embedding model to generate vectors when needed.
3. It stores the vectors and associated document content and metadata.

The exact internal operations depend on the vector-store implementation and configuration. In a production ingestion pipeline, you'd normally load and chunk the actual files first rather than manually constructing documents.

### B. Search for relevant documents

```
import org.springframework.ai.document.Document;
import org.springframework.ai.vectorstore.SearchRequest;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.stereotype.Service;

import java.util.List;

@Service
public class KnowledgeSearchService {

    private final VectorStore vectorStore;

    public KnowledgeSearchService(VectorStore vectorStore) {
        this.vectorStore = vectorStore;
    }

    public List<Document> search(String question) {

        return vectorStore.similaritySearch(
            SearchRequest.builder()
                .query(question)
                .topK(3)
                .build()
        );
    }
}
```

Here, `topK(3)` asks for up to three relevant document chunks.

The vector-store implementation converts the query to an embedding, performs similarity search, and returns matching documents. Exact builder APIs may vary by Spring AI version.

### C. Send retrieved documents to the LLM

You can connect retrieval to `ChatClient`:

```
String answer = chatClient.prompt()
    .advisors(QuestionAnswerAdvisor.builder(vectorStore).build())
    .user("How do I implement a circuit breaker?")
    .call()
    .content();
```

This illustrates the advisor-based RAG pattern available in Spring AI versions that provide `QuestionAnswerAdvisor`. Make sure you include the corresponding advisor dependency and configure your `ChatClient` and `VectorStore`.

The advisor performs retrieval and supplies relevant context to the model. This means you don't have to manually implement every retrieval and prompt-construction step.

## 8. Does the vector store persist the data?

This is especially important for your Redis versus pgvector decision.

| Question                                                             | Answer                                                                |
| -------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Does the embedding exist only in application memory?                 | Not necessarily.                                                      |
| Does `vectorStore.add()` typically store the vector in the database? | Yes, for a properly configured persistent vector store.               |
| Does restarting Spring Boot require embedding every document again?  | No, not if the stored data survives and remains available.            |
| Do Redis vectors survive a restart?                                  | Depends on Redis persistence, deployment, and recovery configuration. |
| Can pgvector retain vectors across application restarts?             | Yes, when stored in a persistent PostgreSQL database.                 |

For example, you can keep your source PDFs and Wiki exports in Azure Blob Storage, use a Spring Boot ingestion service to chunk and embed them, and store the resulting chunks and vectors in PostgreSQL with pgvector or appropriately configured Redis.

When the application restarts, it can query the existing vector store rather than ingesting every source file again.

A robust ingestion process also tracks document versions or content hashes so it can update changed documents and avoid unnecessary duplicate ingestion.

## 9. Recommended architecture for your project

Document storage

Azure Blob Storage

PDFs · Wiki exports · Source files

Spring Boot ingestion service

Load → Extract → Chunk → Embed

pgvector

Persistent vectors and relational data

Redis

Vector search and caching options

Spring AI RAG query service

Embed query → Retrieve context → Call LLM → Answer

For a typical enterprise RAG project, I'd start with PostgreSQL + pgvector if you want durable storage and relational metadata in one place. Choose Redis when its performance characteristics, existing infrastructure, or caching and search capabilities fit your requirements. Either can be suitable when configured and operated correctly.

The most important distinction to remember is:

- Embedding model: Converts text into numbers representing its semantic meaning.
- Vector store: Stores and searches those numerical representations, along with associated text and metadata.
- RAG: Uses the retrieved text as context for an LLM to answer a user's question.
